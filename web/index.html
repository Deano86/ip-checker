CONFIGURATION

Intelligence providers

Keep credentials in .secrets on your server. This dashboard only sees whether a key is configured.

Connect your keys

Copy .secrets.example to .secrets and fill in the four required values. Add IPQS_KEY to enable IPQualityScore. Use simple quoted Bash assignments. Refresh this page when you have saved the file.

IPINFO_KEY='your-token'
IP2_KEY='your-key'
PROXY_KEY='your-key'
SPAMHAUS_KEY='your-dqs-key'
IPQS_KEY='your-ipqs-key' # optional

No keys are submitted through the browser. Configuration status confirms that a value exists; a live check verifies provider access.

GETTING STARTED

A closer look, in three steps.

01

Connect your providers

Add all four API keys to your server’s .secrets file. Keep it out of Git and readable only by the account running the checker.

02

Choose your addresses

Paste up to 500 public IPv4 addresses or import a text file. Add one address per line. Comments and duplicates are handled for you.

03

Follow the signals

Watch results arrive, filter the table and open a row for all provider fields. Export the complete scan as CSV for your review.

Reading your results

Yes means a positive signal. No is an explicit negative. Unknown means the source did not return usable information.

Spamhaus PBL alone is not classified as a threat. Registered CIDRs come from RDAP and may differ from routing prefixes. Flags are evidence to investigate, not a safety guarantee.

History is held in server memory for the latest 20 scans and clears on restart. Export any reports you want to keep. The server allows one active scan at a time.
